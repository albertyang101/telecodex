## Self-Recovery Matrix

- CC `CLAUDE_TURN_HARD_CEILING_S` / reader-loop wedge / tool-busy watchdog maps to TeleCodex `CODEX_TURN_TIMEOUT_MS` plus abort grace. Codex SDK does not expose CC-style stream-json internal redrive, so the stable boundary is the official abort signal, then fatal process restart if the SDK/CLI does not release.
- CC orphan/sibling redrive maps to TeleCodex foreground durable queue replay. TeleCodex must not implement a second semantic dispatcher inside Codex; messages are persisted before execution, claims are heartbeated, stale claims replay after launchd restart, and unhandled visible delivery failures remain pending for replay.
- CC process-tree cleanup maps to `CODEX_PATH=scripts/codex-no-user-config-wrapper.sh`. The wrapper is intentionally thin: it translates SDK `--experimental-json` to official `--json`, preserves stdin, and owns only process-group termination for SDK aborts.
- CC transport deaf / polling conflict recovery maps to grammY 409 bounded retry, pending-update watchdog, and fatal escalation when the current poller cannot be stopped cleanly. This avoids duplicate live pollers.
- CC Telegram delivery retry/phantom guards map only to bounded Bot API writes in this slice. TeleCodex does not retry semantic media delivery here; it prevents delivery hangs from pinning the dispatcher queue.
